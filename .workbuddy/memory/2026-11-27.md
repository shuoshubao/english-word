- 改为「JSON 数据 + 文件系统读取」: 主包 Primary 用 `readFileSync` 同步读；每个分包加 20 字节的 `loader.js`(`export default {}`)，用字面量路径的 callback require 触发分包下载，再用 `FileSystemManager.readFile` 读分包内 JSON；相对路径失败时回退 `/` 绝对路径。
- 关键坑: 分包异步化的 `require` 必须是字面量路径。用 `const trigger = path => (ok, fail) => require(path, ok, fail)` 工厂包装后，微信静态分析识别不到，分包不会打包，实测校验时发现并改回内联字面量。
- `project.config.json` 的 `packOptions.include` 加入 `data/Primary`，保证主包 464KB JSON 不被裁剪；分包 JSON 在分包 root 下自动打包。
- 分包 module not defined: 基础库 3.17.2 下按需注入导致分包 JS 不被注入。关闭 `app.json` 的 `lazyCodeLoading: requiredComponents`，并给 16 个分包都加 `entry: loader.js` 显式声明入口后解决。小程序没有 wx.loadSubpackage 主动下载 API（那是小游戏的）。
- FileSystemManager API 坑: `readFile(Object object)` 只接受一个对象参数，success/fail 回调必须写在对象内部（形如 `success: res => res.data`），不能当第二个回调参数传，否则回调永不触发、Promise 永远 pending → 页面空白且不报错。`readFileSync(path, encoding)` 用字符串。
- 最终方案: 放弃异步 `readFile`，分包词书也统一用同步 `readFileSync`（分包下载在 require 回调里已完成）。`loadSub` 里 `loader.files.map(readBookSync)`。`readBook`/`readFile` 已删除，catalog 只保留一个 `readBookSync`，小学与分包读取路径一致。
- 分包读 json 报 `readFileSync:fail permission denied, open /data/Junior/7-2.json`: 微信代码包里的 .json 默认不作为可读取资源打包，必须在 `project.config.json` 的 `packOptions.include` 显式声明才能用 FileSystemManager 读。小学能读正因它在 include 里。已把 include 从 `data/Primary` 扩到整个 `data` 目录（分包文件归属仍由 app.json subpackages 决定，不会进主包）。
